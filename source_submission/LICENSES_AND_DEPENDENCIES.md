# Licenses and dependencies

Pointer document for the source-code upload. It **references** the existing audits rather
than restating them, so there is one place to update when a dependency changes.

## Canonical sources

| Source | Role |
|---|---|
| [`../README.md`](../README.md) | Scored license table. **Canonical.** The hackathon rule requires every dependency to appear here. |
| [`../docs/licensing.md`](../docs/licensing.md) | Full audit with frozen versions and declared metadata licences, captured 2026-07-30. |
| [`../requirements.txt`](../requirements.txt) | Pinned runtime dependencies. |
| `eval/frozen/environment_manifest.json` | Exact versions used in the frozen benchmark run. |

Do not copy the license table into this file. Two tables drift; one does not.

## Verification before upload

```powershell
# Every non-comment requirement should appear in the README table
Select-String -Path requirements.txt -Pattern '^[a-zA-Z]' |
  ForEach-Object { ($_.Line -split '[=<>]')[0].Trim() } |
  ForEach-Object {
    $hit = Select-String -Path README.md -Pattern $_ -Quiet
    "{0,-28} README: {1}" -f $_, $(if ($hit) { "yes" } else { "MISSING" })
  }
```

Any `MISSING` is a scored-rule violation and must be fixed before upload.

## Known drift, recorded 2026-08-01

`pypdfium2==5.12.1` is present in `requirements.txt` and **is** correctly listed in the
`README.md` license table (BSD-3-Clause OR Apache-2.0; bundled PDFium under a BSD-style
licence). It is **absent** from the table in `docs/licensing.md`.

- Scored rule: **satisfied**, because README is the canonical table.
- Audit completeness: **incomplete**, because `docs/licensing.md` lags by one dependency.

Not fixed here: this task is restricted to submission-control documentation, and
`docs/licensing.md` is an evidence document. Recorded so it is not lost.

Recommended owner action: add the `pypdfium2` row to `docs/licensing.md` on a separate
branch, matching the wording already in README.

## External binary

Tesseract 5.4.0 (Apache-2.0) is **not** a Python package. It is installed separately and
resolved at runtime by `engine/ocr/tesseract_engine.py` via PATH, standard install
locations, or `TESSERACT_CMD`.

The source upload must not bundle the Tesseract binary. Installation instructions belong
in the README.

## Licence categories

Per `docs/licensing.md`, declared runtime licences are permissive (MIT, BSD-3-Clause,
Apache-2.0, MIT-CMU, and combinations). No copyleft source-distribution obligation was
identified for the listed dependencies.

**Two categories remain outside that conclusion and must not be described as approved:**

1. **Provider terms.** Any commercial model provider is governed by its own terms, not by
   the OSS licences above. No provider was called in the frozen benchmark.
2. **Dataset terms.** Organiser-supplied documents carry their own usage terms. The
   synthetic dataset is generated by `data_factory/` and carries none.

Approved wording for both is in
[`../docs/submission/claims_register.md`](../docs/submission/claims_register.md), which
prohibits any claim that commercial or data use is legally approved.
